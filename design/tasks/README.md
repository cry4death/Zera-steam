# Задачи для исполнителей

Роли:

| Кто | Что делает | Доступ к коду |
|---|---|---|
| **Claude Opus** (ревьюер) | пишет задачи, контракты, проверяет и принимает работу, сливает ветки | весь проект |
| **Claude Sonnet 5.5** (Claude Code) | правит существующий код, интегрирует, запускает Godot и тесты | весь проект `Desktop\zera` |
| **ChatGPT (Codex)** | пишет **новые самостоятельные файлы** по контракту | читает `zera`, пишет только в `tasks/inbox/<id>/` |

## Папки

```
tasks/
  README.md        — этот файл: процесс
  BOARD.md         — доска: статусы и порядок задач
  CONTRACTS.md     — общие API между задачами (единственный источник правды)
  M4/              — задачи этапа M4 (S* — Sonnet, G* — ChatGPT)
  inbox/<id>/      — сюда кладётся то, что вернул ChatGPT (не в проект!)
  reports/<id>.md  — отчёт исполнителя
  reviews/<id>.md  — ревью Opus: принято / на доработку + замечания
  templates/       — шаблоны отчёта и ревью
```

## Как выдать задачу

**Sonnet:** открыть новую сессию Claude Code с моделью Sonnet 5.5 в папке `Desktop\zera`
(добавить папку `Desktop\GameZ`) и написать:

> Выполни задачу `C:\Users\Dev\Desktop\GameZ\tasks\M4\S1_enemy_types.md`. Перед началом прочитай `tasks/README.md` и `tasks/CONTRACTS.md`.

**ChatGPT (Codex):** промт из `PROMPTS.md`. Codex сам читает задачу и код и кладёт результат в
`tasks/inbox/<id>/` (+ `notes.md`). В `zera` он ничего не пишет — там в это время работает Sonnet;
в проект файлы переносит ревьюер.

**Потом:** написать Opus «проверь S1» (или G1 и т. д.).

## Правила для Sonnet

1. Проект — git-репозиторий `Desktop\zera`, ветка `main` — принятое состояние.
   Работать в своей ветке `task/<id>` (например `task/s1`), в `main` не коммитить и не сливать.
2. Трогать **только файлы из списка задачи**. Нужно что-то вне списка — написать об этом в
   отчёте, а не править молча.
3. Стиль — как в окружающем коде: GDScript с типами, табы, комментарии по-русски, кратко.
   Packed-массивы для массовых сущностей, без нод на каждого врага/снаряд.
4. Нельзя `draw_circle` в массовой отрисовке (тормозит) — только `PixelArt.draw_dot`.
5. Числа — из `GameZ\BALANCE.md`. Отличие от баланса — только с объяснением в отчёте.
6. Перед сдачей обязательно:
   ```
   & "C:\Users\Dev\Desktop\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe" --headless --path . --import
   ```
   и прогоны из раздела «Проверка» задачи (без ошибок и warning'ов парсера в выводе).
   Замеры производительности — с флагом `--disable-vsync` перед `--path` (иначе FPS упирается в 144);
   сравнивать `horde_ms`/`physics_ms` с `reviews/baseline.md`.
7. Коммит в своей ветке, сообщение `S1: кратко что сделано`.
8. Отчёт — `GameZ\tasks\reports/<id>.md` по шаблону `templates/report.md`:
   что сделано, какие файлы, вывод команд проверки (цифры FPS), скриншоты, отступления от задачи.

## Правила для ChatGPT (повторены в каждой задаче G*)

- Godot **4.7**, GDScript 2.0 со статической типизацией, отступы — табы.
- Отдавать **файл целиком**, одним блоком, без «… остальной код без изменений».
- Только API, перечисленные в задаче. Не выдумывать методы движка/проекта — если чего-то
  не хватает, написать в пояснениях.

## Как проверяет Opus

1. Сверка с критериями приёмки задачи и `CONTRACTS.md`.
2. Чтение диффа (`git diff main...task/<id>`) / файла из inbox.
3. Свои прогоны: `--import`, `--bench`, `--sim`, скриншоты `--shot`.
4. Вердикт в `reviews/<id>.md`: **ПРИНЯТО** (ветка сливается в main / файл переносится в проект)
   или **ДОРАБОТКА** (список замечаний — отдать исполнителю как есть).

## Уровень рассуждений исполнителей (выбирает ревьюер под задачу)

| Задача | Codex (`gpt-6.1-sol`) | Sonnet 5.5 |
|---|---|---|
| Новый файл по готовому контракту, арт, UI, доработка по списку замечаний | `medium` (по умолчанию) | `medium` |
| Мелкая правка, перенос, переименование, обновление чисел/доков | `low` | `low` |
| Интеграция нескольких систем, игровой баланс, правки в горячем коде (horde, weapons) | `high` | `high` |
| Производительность, тонкие/плавающие баги, архитектурные решения | `high` (`xhigh` при повторной неудаче) | `high` / `xhigh` |

Если задача вернулась на доработку дважды, ревьюер поднимает уровень на ступень.
Выбранный уровень записывается в журнал `BOARD.md` при выдаче.
