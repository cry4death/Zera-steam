# Готовые промты для исполнителей

## Sonnet 5.5 (Claude Code) — один промт на любую задачу

Сессия: модель Sonnet 5.5, папка `C:\Users\Dev\Desktop\zera`, добавить папку `C:\Users\Dev\Desktop\GameZ`.
В первой строке поменять ID (S1 / S2 / S3).

```
Задача: S1

Ты исполнитель в проекте игры на Godot 4.7. Проект — C:\Users\Dev\Desktop\zera (git), документы и задачи — C:\Users\Dev\Desktop\GameZ.

1. Прочитай целиком: GameZ\tasks\README.md, GameZ\tasks\CONTRACTS.md, GameZ\tasks\BOARD.md и файл своей задачи в GameZ\tasks\M4\ (имя начинается с ID задачи). Нужные разделы GameZ\BALANCE.md, GameZ\MVP.md и GameZ\tasks\reviews\baseline.md — по ссылкам из задачи.
2. Если есть GameZ\tasks\reviews\<ID>.md с вердиктом ДОРАБОТКА — это повторный заход: исправь только замечания оттуда, в той же ветке.
3. Иначе создай ветку от main: git checkout -b task/<id в нижнем регистре> (например task/s1). Если у задачи есть зависимости — убедись по BOARD.md, что они ПРИНЯТЫ и их файлы есть в main; если нет — остановись и напиши, чего не хватает.
4. Перед правками изучи код, который трогаешь, и пиши в его стиле. Трогай только файлы из раздела «Можно трогать».
5. Выполни все пункты задачи. Godot: C:\Users\Dev\Desktop\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe. После правок всегда --headless --path . --import, затем все команды из раздела «Проверка». Ошибки и warning'и в выводе — исправить.
6. Скриншоты сохраняй в GameZ\tasks\reports\ с префиксом id (s1_bench.png и т. п.) и посмотри их сам.
7. Пройди по критериям приёмки. Невыполнимое — не скрывай, опиши в отчёте.
8. Закоммить в свою ветку: «<ID>: кратко что сделано». В main не коммить и не сливай.
9. Напиши отчёт GameZ\tasks\reports\<ID>.md по шаблону GameZ\tasks\templates\report.md — с дословным выводом команд проверки и цифрами FPS.
10. В конце ответь коротко: ветка, коммит, путь к отчёту, что не получилось. Статусы в BOARD.md не меняй — это делает ревьюер.

Если в задаче что-то противоречит коду или контракту — не придумывай молча: выбери разумный вариант и опиши его в отчёте в «Отступлениях».
```

## ChatGPT (Codex) — задачи G1, G2, G3

Codex: рабочая папка `C:\Users\Dev\Desktop\GameZ`, доступ на чтение к `C:\Users\Dev\Desktop\zera`.
В первой строке поменять ID (G1 / G2 / G3).

```
Задача: G1

Ты исполнитель в проекте игры на Godot 4.7. Проект игры — C:\Users\Dev\Desktop\zera, задачи и документы — C:\Users\Dev\Desktop\GameZ.

ВАЖНО: в папке zera параллельно работает другой исполнитель в своей git-ветке. Ничего в zera не создавай, не меняй, не переключай ветки и не запускай там git-команды, меняющие состояние. Свои файлы пиши ТОЛЬКО в GameZ\tasks\inbox\<ID>\.

1. Прочитай целиком: GameZ\tasks\README.md, GameZ\tasks\CONTRACTS.md и файл своей задачи GameZ\tasks\M4\<ID>_*.md.
2. Если есть GameZ\tasks\reviews\<ID>.md с вердиктом ДОРАБОТКА — исправь только замечания оттуда в своём файле в inbox.
3. Сверь с настоящим кодом в zera те API, которые перечислены в задаче (scripts/*.gd, tools/gen_art.py) и пиши в стиле этих файлов. Новые API из CONTRACTS.md (например Horde.Kind, сигналы S1) в коде могут ещё отсутствовать — опирайся на контракт, не на текущий код.
4. Сделай результат, указанный в задаче, и сохрани в GameZ\tasks\inbox\<ID>\ под указанным там именем.
5. Проверка:
   - G1, G2: скопируй zera во временную папку вне GameZ и zera (без .git и .godot), положи туда свой файл в scripts\, запусти
     "C:\Users\Dev\Desktop\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe" --headless --path <временная папка> --import
     и убедись, что нет ошибок парсинга по твоему файлу (ошибки из-за ещё не сделанных частей контракта S1 — перечисли в notes.md). Для G2 по желанию сделай во временной копии тестовую сцену и скриншоты фаз warn/start/finish в inbox\G2\.
   - G3: запусти скрипт так, чтобы он импортировал gen_art из C:\Users\Dev\Desktop\zera\tools (PYTHONPATH), а PNG писал в GameZ\tasks\inbox\G3\art\ (выстави ga.OUT), и сохрани превью inbox\G3\preview.png. Посмотри превью сам и доработай, если спрайт не читается.
   После проверки временную папку удали.
6. Напиши GameZ\tasks\inbox\<ID>\notes.md по шаблону GameZ\tasks\templates\report.md: что сделано, вывод проверки дословно, отступления от ТЗ и почему, каких API не хватило.
7. В конце ответь коротко: какие файлы лежат в inbox и что не получилось. BOARD.md не меняй.
```

Результаты: G1 → `inbox\G1\hazards.gd`, G2 → `inbox\G2\alarm_overlay.gd`, G3 → `inbox\G3\gen_art_m4.py` + `art\*.png` + `preview.png`.
В проект их переносит ревьюер после проверки.
