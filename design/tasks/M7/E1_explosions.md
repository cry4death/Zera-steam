# E1 — реалистичные взрывы

**Исполнитель:** Codex / Sonnet · **Уровень:** high (VFX + производительность) · **Ветка:** `task/e1` (от main после P1)
**Запрос автора:** «взрывы выглядят нереалистично».

## Сейчас

`weapons.gd::explode()` рисует взрыв как **расширяющееся кольцо `draw_arc` + круглое пятно** (`_blasts` в `_draw`, 0.22 с),
плюс частицы `effects`, свет (W1), звук `explosions/grenade` (A1), гибы. Это читается как «круг», а не взрыв.
Взрывы есть у: гранаты-активки, «Грома»/«Улья», детонатора и цепных детонаций, взрыва толстяка (`hazards.gd`), смерти босса.

## Цель

Взрыв выглядит как взрыв в пиксельном стиле игры: вспышка → огненный шар → клубы дыма, ударная волна по полу и
воздуху, разлёт обломков и искр, подкидывание и разрывание тел, чёрная подпалина на полу, которая остаётся.

## Сделать

1. **Спрайты** — новый `tools/gen_art_fx.py` (поверх `gen_art`, детерминированно) → флипбуки `art/fx_explosion_<size>.png`
   (2–3 варианта, 10–14 кадров: белая вспышка → жёлто-оранжевое ядро → тёмно-красное пламя с рваным краем → серо-чёрный
   дым, шум/турбулентность, без «кругов»), `art/fx_smoke.png` (клубы дыма, 6–8 кадров), `art/fx_debris_*.png`
   (обломки асфальта/металла), `art/fx_scorch_*.png` (подпалины-декали с неровным краем, 3 шт.). Свет сверху-слева,
   палитра проекта. Лист `design/tasks/reports/e1_sheet.png` — посмотри сам.
2. **Система** — новый `scripts/explosions.gd` (`class_name Explosions`, один узел, Packed-массивы/пул, рисование флипбуков
   одним проходом/MultiMesh, без нод на взрыв): `spawn(at: Vector2, radius: float, kind: int)` — размер и состав по радиусу/виду
   (граната, гранатомёт, толстяк — мокрый, кислотно-зелёный оттенок дыма и больше крови, детонатор — меньше, босс — огромный,
   многоступенчатый). Слои: вспышка (1–2 кадра, аддитивно) → огненный шар (флипбук, лёгкий рост) → 3–6 клубов дыма
   поднимаются и расплываются 1.5–3 с → ударная волна (тонкое полупрозрачное искажение/кольцо пыли по полу, **не**
   яркая линия) → 8–20 обломков и искр по дугам с тенью → подпалина в пол (`floor_decals`, под кровью). Тряска камеры по
   расстоянию до игрока. Свет — существующий.
3. **Подключить** во все места взрывов вместо `_blasts`-круга (сам круг удалить), урон/логика взрыва не меняются.
4. **Нагрузка**: цепь детонаций (десятки взрывов за секунду) — лимит одновременных огненных шаров и клубов дыма
   (самые старые/дальние гаснут быстрее), `--alarm` цепь толстяков и смерть босса — худший кадр не хуже main.
5. **`--fx-test`** (оконный): одиночный взрыв гранаты (снимки 0.05 / 0.15 / 0.4 / 1.5 с), гранатомёт по толпе, взрыв
   толстяка, цепь из 20 детонаций, смерть босса — `_seq.png` (раскадровка), `_crowd.png`, `_fat.png`, `_chain.png`, `_boss.png`.

## Можно трогать

`tools/gen_art_fx.py`, `art/fx_*` (новые), `scripts/explosions.gd` (новый), `scripts/weapons.gd` (только вызов и удаление
`_blasts`), `scripts/hazards.gd`, `scripts/game.gd` (подключение узла, смерть босса, `--fx-test`), `scripts/floor_decals.gd`
(API подпалин), `scenes/main.tscn`, отчёт `design/tasks/reports/E1.md`, `e1_*`.

## Проверка
```
godot --headless --path . --import
godot --disable-vsync --path . -- --fx-test --shot=.../e1.png
godot --disable-vsync --path . -- --alarm ; --boss ; --loadout --bench=500 (×2 против main)
```

## Критерии приёмки
- [ ] Взрывы — огонь/дым/волна/обломки/подпалина, без кругов; разные у гранаты, толстяка, босса (раскадровка).
- [ ] Цепи детонаций и смерть босса не хуже main по худшему кадру; bench ≤ +5%. Отчёт `design/tasks/reports/E1.md`.

## Порядок выполнения (решение ревьюера, 2026-10-17)

Пока P1 (оптимизация) правит `weapons.gd`, `effects.gd`, `floor_decals.gd` — **E1 делает всё, кроме подключения**:
спрайты (`gen_art_fx.py`, `art/fx_*`), `scripts/explosions.gd` (рисует подпалины через уже существующий
`floor_decals.stamp(...)`, API не менять), узел в `scenes/main.tscn`, `--fx-test` в `game.gd` (вызывает `Explosions.spawn`
напрямую). В `weapons.gd`, `hazards.gd`, `effects.gd`, `floor_decals.gd` — **не трогать**: подключение во все места
взрывов и удаление круга `_blasts` — отдельным коротким шагом после слияния P1 (E1b). В отчёте — точный список мест
подключения (файл:функция) для E1b.
