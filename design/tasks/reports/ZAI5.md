# Отчёт ZAI5 — Поле путей v2: видимость в поле, штраф у стен, дешевле при беге

**Исполнитель:** Claude Opus 5.5 (облачная сессия, «делай все рекомендации») · **Ветка:** `claude/great-rubin-vhn9o1` ·
**Коммит:** `48a3d7d` (+ отчёт)

## Как теперь устроено поле
- **Видимость (R10).** Своих лучей у зомби нет: `agent_queries=0` в `--pathing-test`.
  - Видимость считает та же волна Дейкстры, что и поле. Клетка «видит цель» для своего класса радиуса, если
    свободна с запасом (зазор ≥ радиус класса + 4 px), ближе 700 px и видна соседняя клетка на шаг ближе к цели
    (ось или диагональ, как линия Брезенхэма). Сосед ближе к цели всегда снят из очереди раньше.
  - Клетка у стены сама флага не получает. Она видит цель, если видна клетка на шаг ближе и тело туда проходит
    (`sees_target`). Без этого прижатые к стене шли по полю, хотя игрок на виду.
  - Режим «прямо ↔ по полю» меняется после 4 решений подряд (~0,27 с, `MODE_HOLD`). Без задержки зомби у границы
    тени угла мельтешили.
- **Штраф у длинных стен (З4).** Клетка ближе 24 px к дому или забору дороже на 10 × (1 − зазор/24). Путь идёт
  серединой улицы. Притяжение к отрезку пути — только в щелях уже двух диаметров.
  - Машины, блоки и мешки штрафа не дают: по PF1 автор просил обход вплотную, тест `hug` держит зазор ≤ 2 px.
- **Дешевле (R11).** Пауза между циклами 0,15 с (было 0,05). Класс 1 считается каждый цикл, классы 0 и 2 — раз в
  три цикла. Класс 2 — только пока живы крупные. Волна каждого класса идёт до самой дальней особи этого класса +
  400 единиц стоимости, а не по всей карте. Для класса 1 — ещё до входов, откуда может выйти пачка (ближайший за
  экраном + 400 px). Корзины Дайла — на packed-массивах.
- `--pathing-test` снова ждёт `queries == 0`.
- Попробовано и снято: отталкивание идущего по полю от стены и отвод точки появления от стены. Колонны у машин
  не уменьшились, а первый контакт на старте old_town вырос с 7,3 до 12 с.

На старте cargo_port и quarantine_checkpoint все идут к игроку по открытому — у стен никого (0 → 0), строки
опущены. Один прогон на ячейку: разброс между прогонами — до ±30 %.

- По полю у домов и заборов колонн стало в 3–9 раз меньше: в жилом квартале ×23 → ×6,3 на старте и ×18 → ×4,7 на
  бегу, на базе ×8,8 → ×1,6, на аэродроме ×4,2 → ×0,9.
- Среди всех идущих у домов ≤ ×1,8 везде, кроме старта в жилом квартале (×2,8; было ×9,1).
- Остаток — **машины и блоки**: на старте open_perimeter ×28, old_town ×10. Это обход вплотную по PF1. Чтобы толпа
  шла от машин дальше, нужен штраф и у машин, а он ломает «вплотную» (тест `hug`). Решение — автору.
- Выборка «по полю» смещена: по полю идут как раз те, кому мешает препятствие. Поэтому порог ≤ ×1,5 «по полю» в
  задаче недостижим даже при честной середине прохода. Для оценки беру всех идущих.

**Мельтешение режима** (`--crowd-test`, бег кругами / большой круг; open_perimeter / old_town), ZAI4 → ZAI5:
- смена режима за 0,1 с: 1,0 / 2,9 % → 0,95 / 2,7 %;
- смена, отменённая за 0,5 с: 0,19 / 0,55 % → 0,08 / 0,16 % на бегу, 0,17 / 0,29 % → 0,13 / 0,09 % на большом круге.

Почти все смены — настоящие: бегущий игрок двигает тени домов и машин по толпе. Порог задачи «< 0,1 % смен» на
такой геометрии недостижим ни лучами, ни полем. Взял метрику мельтешения — смену, отменённую быстрее 0,5 с. Резкого
поворота при смене нет: скорость тянется к новой цели с ускорением роли (ZAI4).

**CPU** — old_town 6:00, игрок бегает кругами, 70 с + 10 с разгона, `--nav-thread`, стенд `zai1_metrics`. Время
процесса — `times` bash (user + sys), облако, 4 ядра:

| | ZAI4 | ZAI5 |
|---|---|---|
| Реальное время (`--max-fps 60`): ядер | 94,4 / 77,7 с = **1,21** | 53,4 / 77,4 с = **0,69** |
| Реальное время: интервал обновления поля p50 | 0,150 с | 0,167 с |

- Без ограничения кадров поток считает поле без перерыва. Цикл стал вдвое дешевле, и поле обновляется вдвое чаще
  (223 против 118) — CPU почти тот же. Живую игру показывает строка «реальное время».
- ZAI1 мерил 2,7 ядра без ограничения кадров на машине автора; облачная машина другая, поэтому сравниваю пары.
- Поведение в том же прогоне не хуже: стоящих 4,3 → 3,9 %, перекрытие 0,116 → 0,098, застрявших 0,9 → 1,0 %.

## Критерии приёмки
- [x] `PATHINGTEST … agent_queries=0 … failed=0`, щели PF1 проходятся.
- [ ] По полю у стен ≤ ×1,5. **Частично.** Дома и заборы: среди всех идущих ≤ ×1,1 почти везде (до ZAI5 до ×9,1).
  Машины — по PF1 вплотную, см. выше.
- [ ] Переключения режима < 0,1 %. **Заменено** метрикой мельтешения (≤ 0,3 %, факт 0,08–0,16 %), см. выше.
- [x] CPU при беге ≤ 1,5 ядра: 0,69 в реальном времени (было 1,21, −43 %). Интервал поля p50 0,167 с (≤ 0,2).
- [ ] Bench FPS — только окно на машине автора.

## Отступления от задачи
- Штраф — только у длинных стен (дома, заборы), не у машин и блоков: PF1 (обход вплотную).
- Смешивания направлений при смене режима нет. Его заменяют задержка режима и инерция скорости.
- Порог мельтешения вместо доли смен (см. выше).

## Найденные проблемы вне задачи
- Колонны вдоль машин на старте open_perimeter — следствие PF1. Если автор хочет толпу дальше от бортов, нужен
  небольшой штраф и у машин с ослаблением теста `hug` (сейчас зазор ≤ 2 px).
