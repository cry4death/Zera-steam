# Отчёт C4 — полировка кампании и тон Z.E.R.A.

Ветка `task/c4`. Исполнитель: Codex начал, Sonnet 5.5 довёл (проверил диф Codex, добавил недостающее). Механика, числа и баланс не менялись — только строки, выбор строки и раскладка подписей.

## Что изменено

### Глобус (`scripts/ui/globe_view.gd`)
Подписи раскладываются в `_layout_labels()` (вызывается из `_draw`), а не по одной при отрисовке:
1. Сначала резервируются прямоугольники всех значков (20×20 px при k=1), затем подписи по приоритету: выбранный регион, регионы с операциями (`[N]`), остальные.
2. Подпись ищется по нормали от центра шара: расстояния 16/30/46/64/86 px, на каждом — сдвиг вдоль касательной 0, ±1, ±2, ±3 шага по 14 px. Прямоугольник должен целиком лежать в дисплее и не пересекать значки и уже поставленные подписи (зазор 1 px).
3. Выноска (значок → край подписи) в строгом проходе не должна резать чужие подписи, чужие значки, а подпись не должна лежать на уже проведённых выносках. Если чистого места нет — второй проход берёт любое свободное.
4. Порядок вариантов: полное имя (строгий проход) → короткое имя («Сев.», «Вост.», «Зап.», «Бл.», «Юж.»; номер операции сохраняется) → полное имя (любое место) → короткое (любое место).
5. У горизонта нормаль может вести за край: выбранной и операционной подписи ищется ближайшее свободное место по сетке внутри дисплея. Обычную подпись в такой ситуации скрывают (значок остаётся).
6. Отрисовка: выноска идёт от значка к ближайшей точке прямоугольника.

В `--globe-test` добавлен плотный перебор: 3 размера дисплея × 3 зума × 3 наклона × 24 поворота × 4 фильтра = 2592 раскладки, выбранный регион меняется на каждом повороте. Проверки: `labels_no_overlap_or_clipping` (подписи в границах, не пересекают значки и друг друга), `selected_and_operation_labels_visible` (выбранные и операционные подписи всегда есть). Кроме того, считается `leader_crossings` — выноски, режущие чужую подпись: 121 из 2592 раскладок (в основном экстремальные наклоны на самом мелком дисплее, где чистого места нет); в трёх скриншотах — 0.

### Итоги (`scripts/run_results.gd`)
- Множитель ДНК раздельно: `multiplier_text()`. Итоговый `dna_mult` делится на множитель операции (`reward.dna_mul`, только при победе и в кампании), остаток — множитель победы. До: «× 2.1 победа». После: «× 1.5 победа · × 1.4 операция». Свободный забег: «× 1.5 победа»; поражение: без множителей.
- Заголовок: над названием добавлена строка «РАПОРТ ОБ ОПЕРАЦИИ».

### Реплики Диспетчера (`game.gd`, константа `DISPATCH`)
Формат анонса: «ДИСПЕТЧЕР: <реплика>» через существующий `_announce`; `hud.gd` не тронут. 2 варианта на событие, вариант выбирается по `Meta.runs + счётчик показов события` (детерминированно, без боевого RNG, сценарий операции не затрагивается), каждое событие объявляется один раз:
- start (когда сошёл баннер операции): «Высадка. Работайте.» / «Канал открыт. Зачистка.»
- trader (закрытие лавки): «Снабжение выдано.» / «Поставка закрыта. Работайте.»
- alarm (фаза WARN, либо ACTIVE без предупреждения): «Всплеск биомассы.» / «Активность растёт. Огонь.»
- approach (9:30): «Объект-7 на подходе.» / «Объект-7. Приготовиться.»
- boss: «Объект-7 уничтожен.» / «Объект-7. Сигнал погас.»
- evac (смерть): «Единица ранена. Эвакуация.» / «Прекратить огонь. Эвакуация.»
- supply (падение контейнера тревоги): «Сброс снабжения.» / «Снабжение. Груз на земле.»

Тест `dispatcher_variants_fit_one_line`: 2–3 варианта, нет переносов, ширина строки ≤ 608 px при 26 pt, повторный вызов даёт другую реплику.
